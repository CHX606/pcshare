## 1. 项目是什么

**一句话**：坐在任意一台电脑前，像操作本机一样管理其他电脑的文件夹、打开上面的软件。不传整块桌面画面，所以不卡。

**背景**：有多台 Windows 电脑，分布在不同网络，现在用远程桌面软件操作，很卡。

**核心思路**：界面画在自己面前这台电脑上，网络上只传很小的指令和结果（“列出这个文件夹”“打开这个软件”）。远程桌面卡，是因为它要把整块屏幕不停地当视频传；这个项目不传画面，要传的数据只有画面的零头。

**不做的事**

- 不做完整的远程桌面
- 不做账号注册、登录体系
- 不做给别人用的分享和多人协作
- 第一版只支持 Windows，其他系统留好位置以后补

**成功标准（验收时逐条量）**

| 指标 | 目标 |
|---|---|
| 同一网络内点开文件夹（5000 项以内） | 100 毫秒内出结果 |
| 不同网络直连时点开文件夹 | 网络往返延迟 + 50 毫秒以内 |
| 发出“打开软件”到对方窗口出现 | 软件自身启动时间 + 200 毫秒以内 |
| 被控端在后台的占用 | 内存 50 MB 以内，空闲时处理器接近 0 |
| 同一网络传文件 | 达到链路速度的 70% 以上 |
| 断线后恢复 | 网络恢复 5 秒内自动连回 |
| 安装包 | 30 MB 以内 |

第 0 阶段已实测的参考值：同一台电脑上两个程序互连，116 项的文件夹 1.4 毫秒，5217 项的 12 毫秒，指令往返 0.3 到 1.2 毫秒，单路传输约 105 MB/秒。

## 3. 总体方案

### 3.1 结构

每台电脑装同一个程序，程序内部分四层：

1. **界面层（控制台）**：一个窗口，里面是网页技术写的界面。
2. **核心层**：设备管理、配对、处理指令、文件传输、缓存。不依赖界面，可以单独运行。
3. **平台隔离层**：所有要和操作系统打交道的事（开软件、回收站、截图、自启动）。先只写 Windows 的实现。
4. **连接层**：负责找到对方、加密、直连、直连不成时走中转。

两台电脑之间：`A 的核心层 ⇄ 加密连接（直连优先，中转兜底）⇄ B 的核心层`。

### 3.2 关键设计决定

| 序号 | 决定 | 选择 | 理由 |
|---|---|---|---|
| D1 | 程序形态 | 一个程序、两种身份：既是控制台，也是被控端 | 坐在哪台前面都能用，只维护一个安装包 |
| D2 | 运行方式 | 随用户登录启动，运行在用户的桌面环境里，**不做成系统服务** | 系统服务环境里打开的软件没有窗口。第 0 阶段已验证：在正常桌面环境里按指令打开软件，窗口能正常出现 |
| D3 | 设备身份 | 每台设备一对密钥，公开的那一半就是“身份码”（64 位十六进制） | 不依赖网络地址，换网络也认得；连接天然加密和防冒充 |
| D4 | 连接 | 用开源库 iroh：直连优先（打洞），公共中转兜底；一条长连接上每条指令走一条独立的数据流 | 自带身份、加密、打洞、中转，不用自己造；多条数据流互不堵塞 |
| D5 | 牵线和中转服务器 | 先用 iroh 的公共服务器；不理想就自建；最后的退路是组网工具 | 详见第 8 节风险 1 |
| D6 | 界面技术 | Tauri 2 做壳，界面用 React + TypeScript | 安装包小、占用低；React 资料最多，交给 AI 执行最不容易出错 |
| D7 | 消息格式 | 控制消息用 JSON，带版本号；文件内容走原始字节 | 好调试；文件不经编码，速度不打折 |
| D8 | 多系统 | 核心层只调用平台隔离层的接口，不直接碰系统 | 加新系统时只补一层 |
| D9 | 权限 | 每台已配对设备一份权限表，被控端执行每条指令前检查 | 见第 7 节 |
| D10 | 代理和 VPN | 程序不擅自绕开用户的代理；需要直连时由用户在代理里加规则，或明确打开“绑定物理网卡”开关 | 绕开代理会暴露真实地址，必须由用户自己决定 |

### 3.3 一次操作怎么走（以点开文件夹为例）

1. 界面向核心层要某台设备某个文件夹的内容。
2. 核心层如果有上次的缓存，立刻交给界面显示，并标记“刷新中”。
3. 核心层在通往那台设备的长连接上开一条数据流，发出“列目录”指令。
4. 对方核对权限，读目录，分批发回。
5. 核心层更新缓存，通知界面只刷新有变化的行。
6. 对方登记“这个文件夹有变化就通知我”，之后的增删改主动推送过来。

顺滑感来自三点：第 2 步让界面不等网络；第 5 步不整页重画；第 6 步不用反复刷新。

### 3.4 界面设计

**主窗口布局**

- **左栏：设备列表**。每台设备一行：名称、在线圆点、线路（直连 / 中转）、延迟。底部是“添加设备”和设置。
- **顶部页签**：文件 · 软件 · 进程 · 更多（截图、命令行、电源等第 3 阶段功能）。
- **底部状态条**：项数、选中数、连接状态。传输时可展开成传输面板。

**文件页**

- 路径栏：每一级都能点，也能直接输入或粘贴路径。
- 工具条：后退、前进、上一级、刷新、新建文件夹、上传、粘贴。
- 列表：名称、修改时间、类型、大小。支持多选、右键菜单、按列排序。只画看得见的行（虚拟滚动）。
- 键盘：回车进入，退格回上一级，F2 重命名，Delete 删除，Ctrl+C / Ctrl+V 跨设备复制粘贴，直接打字跳到同名开头的项。
- 双栏模式：左边电脑 A，右边电脑 B，两边互拖。

**软件页**

- 顶部搜索框，打开页面时光标就在里面。
- 软件列表带图标，可收藏置顶。回车打开第一个匹配项。
- 打开后在角落提示结果：“已在书房电脑上打开 微信”，没检测到新窗口时提示“可能本来就开着”。

**进程页**

- 列表：名称、窗口标题、内存、处理器占用。可按列排序，可结束进程（要确认）。

**各种状态的统一做法**

- 加载中：先显示缓存，角落转圈，不遮挡操作。
- 设备离线：列表变灰，保留最后一次的内容，顶部一条提示和“重试”。
- 出错：用一句人话说明原因和下一步，比如“对方没有授权读取这个文件夹”，不直接显示技术错误码。

```

├─ 策划书/                  本文档

│  ├─ platform/            平台隔离层：接口定义 + Windows 实现
│  ├─ core/                核心：身份、配对、连接、文件、传输、软件、进程
│  └─ agent/               不带界面的可执行程序，也是命令行工具

│  ├─ src-tauri/           Rust 一侧：把 core 接到界面上
│  └─ src/                 界面（React）
```

### 5.2 各部分的职责和边界

| 部分 | 负责 | 不许做 |
|---|---|---|
| `proto` | 定义所有消息和编码方式 | 不联网，不碰文件系统 |

## 6. 通信协议

### 6.1 基本约定

- **协议名**：正式版用 `pcshare/1`，配对用 `pcshare/pair/1`。验证工具用的是 `pcshare/probe/0`。有不兼容的改动时把数字加一。
- **帧**：4 字节长度（大端）+ JSON 正文。单帧上限 16 MB，更大的内容分多帧。
- **请求**：`{"v":1,"cmd":"fs.list","args":{...}}`
- **成功回复**：`{"ok":true,"data":{...}}`
- **失败回复**：`{"ok":false,"err":{"code":"not_found","msg":"给人看的一句话"}}`

### 6.2 三种数据流

| 类型 | 用法 |
|---|---|
| 请求—回复 | 控制端开一条双向流，写一帧请求（后面可以跟原始数据），对方回一帧回复（后面可以跟原始数据），结束 |
| 订阅 | 一条长期的双向流，对方持续推送事件帧：目录变化、进程变化、设备状态 |
| 传输 | 每个文件一条流。并发数由传输队列控制，默认 4 |

### 6.3 错误码

`unauthorized`（没配对）· `forbidden`（权限不够）· `not_found` · `already_exists` · `busy`（文件被占用）· `invalid`（参数不对）· `unsupported`（对方版本不认识这条指令）· `io` · `cancelled` · `internal`

### 6.4 指令表

| 指令 | 作用 | 需要的权限 | 阶段 |
|---|---|---|---|
| `sys.hello` | 交换协议版本、程序版本、设备名、系统类型、支持的功能 | 已配对 | 1 |
| `sys.ping` | 测延迟、保活 | 已配对 | 1 |
| `sys.info` | 电脑名、用户、桌面状态、磁盘、内存 | 已配对 | 1 |
| `fs.roots` | 盘符和常用文件夹（桌面、下载、文档） | 读文件 | 1 |
| `fs.list` | 列目录，支持分批 | 读文件 | 1 |
| `fs.stat` | 单个文件或文件夹的信息 | 读文件 | 1 |
| `fs.mkdir` `fs.rename` `fs.copy` `fs.move` `fs.delete` | 文件操作。复制和移动在对方本机内完成，返回任务号，进度走事件 | 写文件 | 1 |
| `fs.read` | 从指定位置读一段，返回原始字节 | 读文件 | 1 |

## 7. 安全设计

这个程序等于给电脑开了一扇远程操作的门，门锁要先设计好。

### 7.1 要防的情况

| 情况 | 对策 |
|---|---|
| 陌生设备连进来 | 没配对的设备一律拒绝；配对必须有人在被控电脑前确认 |
| 已配对的设备丢了或被别人拿到 | 任意一台都能把它从名单里移除；高风险功能默认关闭 |
| 中转服务器偷看 | 数据在两台电脑之间加密，中转只看得到流量大小 |
| 同一个局域网里的其他人 | 同样需要配对，局域网内不免检 |
| 自己手滑 | 删除进回收站；覆盖、永久删除、关机要再确认一次 |

### 7.2 配对流程

1. 在被控电脑上点“添加设备”，界面显示本机身份码和一个 6 位配对码，5 分钟内有效。
2. 在控制电脑上输入对方的身份码和配对码（也可以粘贴一整串“邀请码”）。
3. 控制电脑按身份码连过去，在加密连接里出示配对码。连接本身已经由双方密钥保证没被冒充，配对码只用来证明“发起的人就在那台电脑旁边”。
4. 被控电脑弹窗：显示对方设备名和身份码后 8 位，由人点“允许”，并选权限档。
5. 双方把对方记进已配对名单。默认互相授权，也可以只授权单向。
6. 配对码输错 5 次立即作废，防止猜。

### 7.3 权限档

| 权限 | 默认 |
|---|---|
| 读文件 | 开 |
| 写文件 | 开 |
| 开软件、管进程 | 开 |
| 截图 | 关 |
| 点按 | 关 |
| 命令行 | 关 |
| 电源 | 关 |

另外可以设“只开放这几个文件夹”。被控端每条指令执行前都按这张表检查，不够就回 `forbidden`。

### 7.4 其他要求

- **密钥保存**：私钥用 Windows 的数据保护接口加密后存在用户目录里，不放在程序旁边。验证工具为了省事是明文放在程序旁边的，正式版不能这样。
- **操作记录**：被控端记下“谁、什么时候、做了什么”，按天滚动，保留 30 天，界面里能查看。
- **路径处理**：所有路径先规范化，拒绝用 `..` 跳出开放范围。
- **不开固定端口**：程序不监听固定的公网端口。iroh 默认会尝试让路由器自动开一个端口映射来提高直连成功率，是否保留见第 9 节。
- **未签名提示**：自己编的程序没有数字签名，第一次运行会被 Windows 的安全提示和防火墙拦一下，需要手动放行。正式分发前再考虑买签名证书。

## 8. 风险清单

| 序号 | 风险 | 现状 | 应对 |
|---|---|---|---|
| 1 | iroh 的公共服务器在国内不好连 | 实测经代理访问时延迟 0.6 到 1.6 秒；不经代理的情况没测 | 第 0 阶段的剩余任务先实测。不行就自建中转（见第二册任务 0.7），再不行用组网工具 |
| 2 | 代理的虚拟网卡模式干扰直连 | 已确认：开着这种模式时，对方拿到的是代理出口的地址，IPv6 也可能被整个拦掉 | 三种办法见第二册任务 0.5，由你选 |
| 3 | 家用路由器不利于打洞 | 没测 | 优先走 IPv6；不行走中转 |
| 4 | Windows 的权限确认框没人点 | 开发机是管理员账户，不会弹框，没法在这台上复现 | 第 1 阶段在普通账户的电脑上专门测；方案见第二册任务 1.9 |
| 5 | 杀毒软件或系统拦截 | 没遇到 | 说明文档里写清放行步骤 |
| 6 | 实时画面工作量大、效果受网络限制 | 没开始 | 放在第 4 阶段，前面用截图和点按顶着 |
| 7 | iroh 接口变化 | 1.0 之后官方承诺接口稳定 | 提交 `Cargo.lock` 锁定版本；升级前先读更新说明 |
| 8 | 执行时偏离方案 | — | 每个任务都有完成标准；一次只做一个任务；做完先自测再往下 |

## 10. 术语

| 词 | 意思 |
|---|---|
| 被控端 | 被别的电脑操作的那一方 |
| 控制台 | 你操作用的界面 |
| 身份码 | 一台设备的唯一标识，64 位字母数字，可以公开 |
| 配对 | 两台设备互相登记并经人确认，之后才能互相操作 |
| 直连 | 两台电脑直接通信，不经过第三方 |
| 打洞 | 让两台各自在路由器后面的电脑建立直连的技术 |
| 中转服务器 | 直连不成时帮忙转发数据的公网服务器；也负责帮两台电脑找到对方 |
| 组网工具 | 把不同地方的电脑连成一个虚拟局域网的软件，如 Tailscale、ZeroTier |
| 虚拟网卡模式 | 代理软件接管电脑全部流量的一种模式 |
| 桌面环境 | 用户登录后看到的那个桌面。程序必须运行在这里，打开的软件才有窗口 |
