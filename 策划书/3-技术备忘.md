## 3. iroh 1.4.1 的用法（已编译运行）

老资料里的名字很多已经变了：`NodeId` 现在叫 `EndpointId`，`discovery` 现在叫 `address_lookup`，底层的 QUIC 库从 `quinn` 换成了 `noq`（接口基本一样）。以本节和已下载的源码为准。

源码位置：`E:\DevTools\Rust\cargo\registry\src\index.crates.io-*\iroh-1.4.1\`

### 3.1 建立端点

```rust
use iroh::endpoint::presets;
use iroh::{Endpoint, SecretKey};

let key = SecretKey::generate();                 // 也可以 SecretKey::from_bytes(&[u8; 32])
let endpoint = Endpoint::builder(presets::N0)    // N0：用官方的地址查询服务和公共中转
    .secret_key(key)
    .alpns(vec![b"pcshare/1".to_vec()])          // 只有要接受连接时才需要
    .bind()
    .await?;

let id = endpoint.id();                          // 身份码，Display 出来是 64 位十六进制
endpoint.online().await;                         // 连上中转才返回；本身没有超时，要自己包一层 timeout
```

- 预设有四个：`Empty`、`Minimal`（只设加密库）、`N0`、`N0DisableRelay`。
- 身份码可以直接从字符串解析：`text.parse::<EndpointId>()`。
- `SecretKey` 没有实现 `Display`，要保存就用 `to_bytes()` 自己转。

### 3.2 接受连接

```rust
while let Some(incoming) = endpoint.accept().await {
    tokio::spawn(async move {
        let conn = incoming.await?;              // 握手
        let peer = conn.remote_id();             // 对方身份码，据此判断是否已配对
        while let Ok((send, recv)) = conn.accept_bi().await {
            // 每条指令一条流，各自处理
        }
        anyhow::Ok(())
    });
}
```

### 3.3 主动连接和收发

```rust
let conn = endpoint.connect(peer_id, b"pcshare/1").await?;   // 只给身份码也能连，靠地址查询服务找对方
let (mut send, mut recv) = conn.open_bi().await?;
send.write_all(&bytes).await?;
send.finish()?;                                  // 注意：finish 不是异步的
recv.read_exact(&mut buf).await?;                // 读满
let n = recv.read(&mut buf).await?;              // 返回 Option<usize>，None 表示对方已结束
conn.close(0u32.into(), b"bye");
endpoint.close().await;                          // 退出前调用，确保关闭消息发出去
```

- 一条流要等发起方**真的写了数据**，对方的 `accept_bi` 才会返回。
- 要确保对方读完再断开，可以在 `finish()` 之后等 `send.stopped().await`。
- 想不依赖地址查询服务：`EndpointAddr::new(id).with_relay_url(url)`，把它传给 `connect`。

### 3.4 看线路是直连还是中转

```rust
for path in conn.paths().iter() {
    path.remote_addr();    // TransportAddr::Relay(url) 或 TransportAddr::Ip(addr)
    path.is_ip();          // 直连
    path.is_relay();       // 中转
    path.is_selected();    // 当前正在用的那条
    path.rtt();            // 这条线路的延迟
}
```

一条连接通常先有一条中转线路，打洞成功后多出一条直连并切换过去。`conn.path_events()` 可以订阅变化。

### 3.5 中转服务器

- 公共中转的主机名：`use1-1`（北美东部）、`usw1-1`（北美西部）、`euc1-1`（欧洲）、`aps1-1`（亚太），后面都是 `.relay.n0.iroh.link`。
- 官方说明：公共中转对中转流量有限速，随时可能调整。只适合牵线和兜底。
- 改用自己的中转：`.relay_mode(RelayMode::custom(["https://你的域名".parse()?]))`。
- 中转连接状态：`endpoint.home_relay_status()`。

### 3.6 网络体检（需要 `unstable-net-report` 特性）

```rust
use iroh::Watcher;
let mut watcher = endpoint.net_report();
let report = watcher.initialized().await;
// report.udp_v4 / udp_v6                 IPv4、IPv6 能不能收发
// report.mapping_varies_by_dest_ipv4     Some(false) = 路由器对直连友好；Some(true) = 不友好
// report.global_v4 / global_v6           对外地址
// report.relay_latency.iter()            到各中转服务器的延迟
// report.preferred_relay                 首选中转
```

这个接口官方标注为不稳定，升级版本后可能变。

## 4. Windows 上已验证的做法

代码都在 `probe/src/win.rs`，可以直接搬。

| 要做的事 | 做法 | 注意 |
|---|---|---|
| 打开程序、文件、快捷方式 | `ShellExecuteW`，动作为 `open` | 放在阻塞线程里调用；调用前 `CoInitializeEx`，之后 `CoUninitialize`；返回值大于 32 才算成功 |
| 打开应用商店软件 | 目标写成 `shell:AppsFolder\<软件标识>` | 同样走 `ShellExecuteW` |
| 列出已装软件 | 调用系统脚本工具执行 `Get-StartApps`，转成 JSON | 约 1 秒；要先把输出编码设成 UTF-8；用 `CREATE_NO_WINDOW` 避免闪黑窗；阶段 2 换成原生接口 |
| 判断软件窗口有没有出现 | 打开前后各用 `EnumWindows` 枚举一次带标题的可见窗口，比较差异 | 软件本来就开着时不会有新窗口，不算失败 |
| 判断程序所处的环境 | `ProcessIdToSessionId` 和 `WTSGetActiveConsoleSessionId` | 会话号为 0 说明在系统服务环境里，打开的软件不会有窗口 |
| 判断是否锁屏 | `OpenInputDesktop` 打不开就是锁屏或权限确认界面 | — |
| 判断是否管理员权限 | 读进程令牌的提升状态 | — |
| 列盘符 | `GetLogicalDrives` | — |

**Rust 2024 版的写法**：声明系统接口要写成 `unsafe extern "system" { ... }`，调用时再包一层 `unsafe`。

## 6. 已知情况和坑

1. **代理的虚拟网卡模式会让直连测试失真。** 开着它时：程序看到的对外地址是代理出口而不是宽带；到公共服务器的延迟很高；IPv6 可能被代理的防泄漏规则整个拦掉（表现为连接立刻失败，提示没有访问权限）。同一局域网内的直连不受影响。处理办法见第二册任务 0.5。
2. **这台开发机测不出权限确认框的问题。** 因为用的是内置管理员账户。必须在普通账户的电脑上测。
3. **程序名不一定指向你以为的软件。** 这台电脑上 `notepad` 实际打开的是另一个编辑器。验证“有没有窗口”时不要假设窗口标题。
4. **应用商店软件打开后可能检测到两个同名窗口**（外框和内容各一个），属于正常。
5. **程序输出的中文在管道里会乱码**，窗口里正常。见第 1 节。
6. **批处理文件里不要写中文**，系统会按本地编码读，容易乱码。要给用户提示，让程序自己打印。
7. **自己编的程序没有数字签名**，拷到别的电脑第一次运行会被安全提示拦一下。
8. **`online()` 没有超时**，没网时会一直等。启动流程里不要无条件等它。
9. **未授权的拒绝要先回话再断开**，否则对方只看到“连接断了”，不知道原因。
